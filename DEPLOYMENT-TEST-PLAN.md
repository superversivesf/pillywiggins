## 1. Overview

This document defines the formal test plan and runnable validation suite for deploying the Pillywiggins agent council. It covers:

- **Pre-deployment infrastructure verification** (the three CRITICAL blockers that will cause hard failure on first `docker compose up`).
- **Smoke tests** — quick end-to-end checks that prove each subsystem is alive.
- **Functional tests** — exercising each major behavior: adapter handshakes, memory, council memory, skills, scheduling, agent-to-agent messaging, model switching, and history compaction.
- **Regression protocol** — what to re-run after any code change.
- **Failure triage** — mapping symptoms to root causes so operators can self-service.
- **Non-Docker execution** — how to point the validation suite at an already-running stack (host Ollama, remote Postgres, etc.).

### Scope

This plan tests the **Docker Compose deployment path** as defined in `docker-compose.yaml.example` and generated by the onboard wizard (`pillywiggins onboard`). It validates the canonical architecture: PostgreSQL + pgvector, Redis, NATS JetStream, Ollama (external), and the agent runtime.

## 2. Pre-Deployment Checklist

Run this checklist *before* `docker compose up`. Every item must be green.

| Step | Command / Action | Expected Result | Failure Mode |
|------|-----------------|-----------------|--------------|
| 2.1 | `cp env.example .env` | `.env` exists in project root. | Docker Compose fails immediately: `env_file: .env` referenced but missing. |
| 2.2 | Edit `.env` and set real `PUCK_TELEGRAM_TOKEN` | Token non-empty. | Bot starts but cannot poll Telegram; logs `Unauthorized`. |
| 2.3 | `cp agents.yaml.example agents.yaml` | `agents.yaml` exists in project root. | Docker Compose creates `agents.yaml` as a **directory** due to bind mount, causing `IsADirectoryError` on app start. |
| 2.4 | Verify `./personalities/` contains the YAML referenced by `PERSONALITY_FILE` | File exists (e.g., `./personalities/puck.yaml`). | Container exits with `FileNotFoundError` on personality load. |
| 2.5 | Verify Ollama is installed and running on host | `curl http://localhost:11434/api/tags` returns 200 JSON. | `LLM_BASE_URL` unreachable; agent fails on first message with connection refused. |
| 2.6 | Verify Ollama has the chosen model pulled | `ollama list` shows `qwen3.5:8b` (or whatever `MODEL_NAME` is set to). | Model not found error; agent fails on first generation. |
| 2.7 | `docker compose config` | No errors; services resolved. | Compose syntax error or missing env substitution. |
| 2.8 | `python -m py_compile tests/deployment/validate.py` | No output (success). | Syntax error in validation script. |

### Hardware / Host Prerequisites

| Requirement | Minimum | Verification |
|-------------|---------|------------|
| Docker Engine | ≥ 20.10 (for `host.docker.internal:host-gateway`) | `docker version` |
| docker compose | ≥ 2.0 | `docker compose version` |
| Ollama | Running on host GPU or CPU | `ollama --version` |
| Model downloaded | `qwen3.5:8b` (or configured `MODEL_NAME`) | `ollama list` |
| Host ports free | 5432, 6379, 4222, 8222, 8080, 8888 | `lsof -i :5432` etc. |

## 3. Smoke Tests (After `docker compose up -d`)

Smoke tests verify the stack is minimally alive. Execute in order.

### 3.1 Health Endpoint (All Services)

```bash
# Wait ~10s after compose up for Postgres to finish init
curl -s http://localhost:8080/healthz | jq .
```

**Expected:**
```json
{
  "status": "ok",
  "checks": {
    "postgres": "ok",
    "redis": "ok",
    "llm": "ok",
    "nats": "ok"
  }
}
```

**Actual behavior:** If any check is not `"ok"`, the endpoint returns HTTP `503` with `"status": "degraded"`.

### 3.2 Telegram Bot Handshake

Send `/start` or `!help` to the bot in Telegram.

**Expected:** Bot replies with help text within ~5s. Typing indicator visible briefly.

### 3.3 Discord Bot Handshake

Send `!help` in an authorized Discord channel.

**Expected:** Bot replies with command list.

### 3.4 LLM Generation

Ask: *"What is 2+2?"*

**Expected:** Response arrives within ~5–15 seconds (local Ollama on RTX 5060 Ti).

### 3.5 Memory Persistence

1. Ask: *"Remember that my favorite color is teal."*
2. Restart the agent container: `docker compose restart puck`
3. Ask: *"What did I just ask you?"*

**Expected:** Bot answers "teal" or references the prior question.

### 3.6 Private Memory Isolation (Multi-Agent)

Requires ≥2 agents running. Ask Agent A a secret. Ask Agent B: *"What did I tell Agent A?"*

**Expected:** Agent B does not know the secret. Council memory may contain an insight, but private memory is RLS-isolated.

### 3.7 Skill Execution

Ask: *"Roll a d20."*

**Expected:** Bot invokes `roll_dice` skill and returns a number 1–20.

### 3.8 Skill Building Flow

Ask: *"Build a skill called reverse_string that takes a string and returns its reverse. Test it with 'hello' → 'olleh'. Show me the code and test results, then deploy it if tests pass."*

**Expected:**
- Draft generated
- Test output shows `"olleh"`
- Review flag cleared
- Approval gate triggered
- Deploy writes to `skills/` and broadcasts via NATS
- Subsequent message "Can you reverse 'pillywiggins'?" uses the new skill.

### 3.9 Scheduled Task

Use `schedule_task` tool or add a schedule in personality YAML. Example: *"Schedule a daily reminder at 9am to say 'Good morning!'"*

**Expected:** Task appears in `list_scheduled_tasks`. Fires at expected time and produces a message.

### 3.10 Agent-to-Agent Direct Message

From Agent A: *"Send a message to the agent puck-discord saying 'Hello from Telegram!'"*

**Expected:** Target agent receives and processes the message. NATS direct subject `council.direct.{agent_id}` used.

### 3.11 Council Broadcast

Trigger `share_to_council` or observe skill deploy announcement. Then from any agent: *"Search the council memory for anything about skill deployments."*

**Expected:** All agents' council memory searches surface the broadcast.

### 3.12 History Compaction

Send `!compact`.

**Expected:** Old messages summarized; new context preserved. Conversation length drops but personality and core facts remain.

### 3.13 Model Switching

Send `!models`, then `!model qwen3.5:8b`.

**Expected:** New model used for subsequent messages. `!status` confirms the switch.

## 4. Functional Tests (Subsystem by Subsystem)

These map each subsystem to its verification method.

| Subsystem | How to Test | Success Criteria |
|-----------|-------------|----------------|
| **Adapter handshake** | Send `!help` / `!status` via Telegram or Discord | UnifiedMessage produced; bot responds with command list and agent metadata |
| **Private memory recall** | "Remember that my favorite color is teal." → "What is my favorite color?" | Private memory table entry created; RLS policy `private_memory_isolation` enforced across agents |
| **Council memory** | "Tell the council that the project deadline moved to Friday." → "Search the council memory for anything about deadlines." | Council memory entry with tag `deadline`; searchable by all agents |
| **Skills execution** | "Roll a d20." | Skill `roll_dice` imported, `run()` executed, result returned in <30s |
| **Skill building** | Build → test → review → deploy flow for `reverse_string` | AST validation passes; dangerous-pattern scan clean; user approval gate cleared; file written to `skills/`; NATS broadcast sent |
| **Scheduling** | Add cron/interval task via `schedule_task` or YAML | `AsyncIOScheduler` + `RedisJobStore` persists job; fires at trigger time; `misfire_grace_time=300` honored |
| **Agent-to-agent messaging** | `send_message_to_agent` from Agent A to Agent B | NATS JetStream direct subject `council.direct.{agent_id}` delivers; target processes within its `asyncio.Lock` |
| **Model switching** | `!model qwen3.5:8b` | New model name persisted; subsequent LLM calls use updated `model_name`; fallback to default if model absent |
| **History compaction** | `!compact` | Old messages summarized by LLM; Redis cache truncated to `COMPACT_KEEP_MESSAGES=6`; PostgreSQL fallback JSONB updated |

## 5. What NOT to Test Yet

These are intentionally stubbed or missing; testing them will produce false failures.

- **Slack, Matrix, Email adapters** — `ChannelType` enum exists, but adapters are not implemented.
- **Rate limiting (10 LLM calls/min/agent)** — No code enforces this yet.
- **Structured JSON logging** — Plain text logs only.
- **Periodic automatic memory consolidation** — `compact_history()` exists, but nothing schedules it automatically.
- **Skill file-watching auto-reload** — Skills reload only on restart or NATS `skill_deployed` event.
- **Scheduler builtins `memory_review`, `skill_reload`, `custom`** — Log only; no real logic.
- **vLLM backend** — Target is Ollama for now. vLLM is a future upgrade path.

## 6. Regression Tests

After any code change to adapters, brain, memory, scheduling, or compose topology, re-run **all** of the following before merging:

| Suite | Command | Purpose |
|-------|---------|---------|
| Unit tests | `pytest tests/ -q` | ~40 test files covering all modules. |
| Static analysis | `python -m py_compile src/pillywiggins/**/*.py` | Syntax validation across the package. |
| Compose health | `docker compose up -d --build` then loop `curl localhost:8080/healthz` for 60s | All services reach healthy state without manual file copies. |
| Onboard wizard E2E | `pillywiggins onboard` + complete interactive flow + `docker compose up` | Wizard produces runnable configs. |
| Deployment validator | `python tests/deployment/validate.py` | Passes all subsystem checks (§7). |
| Infra smoke (optional) | `pytest tests/test_infra_smoke.py -v` | Docker Compose infrastructure tests (skipped if Docker unavailable). |

## 8. Failure Triage

When a smoke or functional test fails, use this decision tree.

### Health Endpoint Returns `503` with a Degraded Check

| Symptom | Root Cause | Fix |
|---------|------------|-----|
| `postgres: error: connection refused` | Postgres container not running or wrong `DATABASE_URL` | `docker compose ps postgres`; verify `.env` `DATABASE_URL` matches compose network hostname (`postgres:5432` inside container, `localhost:5432` from host). |
| `postgres: ok` but private memory fails | RLS policy missing or `app.agent_id` not set | Run `scripts/init-db.sql` in Postgres container; verify `private_memory_isolation` policy exists. |
| `redis: error: connection refused` | Redis container not running or wrong `REDIS_URL` | `docker compose ps redis`; verify `REDIS_URL=redis://redis:6379/0` internally. |
| `llm: error: connection refused` | Ollama not running on host, or model not pulled | `curl http://localhost:11434/api/tags` from host; `ollama list` must show configured model. |
| `llm: error: status 503` | Ollama running but model not loaded in VRAM | Pull model: `ollama pull qwen3.5:8b`. |
| `nats: error: connection refused` | NATS container not running or JetStream not enabled | `docker compose ps nats`; verify NATS command includes `-js`. |

### Bot Does Not Reply to Messages

| Symptom | Root Cause | Fix |
|---------|------------|-----|
| No typing indicator | Bot not running or adapter crashed | `docker compose logs -f puck`; look for startup errors. |
| Typing indicator, no reply | LLM unreachable or timeout | Check health endpoint LLM check; verify Ollama model is loaded. |
| Reply is generic / forgetful | Redis conversation cache lost on restart | Check if Redis is persistent (`appendonly yes`); verify `conversation_cache` PostgreSQL fallback is reachable. |
| `Unauthorized` in logs | `TELEGRAM_BOT_TOKEN` invalid or revoked | Re-generate via @BotFather; update `.env`; restart. |

### Skill Execution Fails

| Symptom | Root Cause | Fix |
|---------|------------|-----|
| "I don't know how to roll dice" | Skill registry empty or `skills/` mount missing | Verify `skills/` volume is mounted in compose; check `registry.json` and filesystem scan in `SkillRegistry.load_all()`. |
| Skill returns timeout | Subprocess in sandbox exceeded 30s | Check `SANDBOX_SKILLS` env var; verify skill does not spawn a long-running process. |
| SSRF error | `URLFilter` blocked an internal IP | Skill attempted to access private range; review skill code or whitelist. |

### Agent-to-Agent Messaging Fails

| Symptom | Root Cause | Fix |
|---------|------------|-----|
| Target agent never receives | NATS stream `COUNCIL` not created | Verify NATS started with `-js`; check `nats stream ls` via NATS monitoring port 8222. |
| Message received but not processed | Target adapter not running or crashed | `docker compose logs {target-agent}`; verify target is healthy. |

### Scheduled Task Never Fires

| Symptom | Root Cause | Fix |
|---------|------------|-----|
| Task missing from list | `RedisJobStore` unreachable or scheduler not started | Verify `SCHEDULER_ENABLED=true`; check Redis connection and APScheduler logs. |
| Task present, never fires | Cron expression invalid or system clock drift | Validate cron with APScheduler logs; ensure `replace_existing=True` is set. |
| Task fires once then stops | `misfire_grace_time` exceeded or container restarted | Check `misfire_grace_time=300` in scheduler config; verify Redis persistence. |

### Docker Compose Issues

| Symptom | Root Cause | Fix |
|---------|------------|-----|
| `env_file: .env` error | `.env` missing | `cp env.example .env`; fill in real tokens. |
| `IsADirectoryError` for `agents.yaml` | Bind mount created a directory because file was absent | `cp agents.yaml.example agents.yaml` before any compose up. |
| Ports already in use | Another Postgres/Redis/NATS on host | Stop host services or remap ports in compose. |
| Agent container restart loop | `depends_on: condition: service_started` instead of `service_healthy` | Ensure generated compose uses `condition: service_healthy` for redis and nats. |

## 9. Running Without Docker

The validation suite (`tests/deployment/validate.py`) can execute against a non-Docker environment if all dependencies are reachable on the host or via remote URLs.

### Prerequisites (Host / Non-Docker)

| Service | Host Install | Default URL |
|---------|-------------|-------------|
| PostgreSQL + pgvector | `pgvector/pgvector:pg16` image or host install | `postgresql://pillywiggins:changeme@localhost:5432/pillywiggins` |
| Redis | `redis-server` or `redis:7-alpine` image | `redis://localhost:6379/0` |
| NATS with JetStream | `nats-server -js` | `nats://localhost:4222` |
| Ollama | `ollama` binary running on host GPU/CPU | `http://localhost:11434` |
| Agent health endpoint | Run agent with `HEALTH_PORT=8080` | `http://localhost:8080/healthz` |

### Running the Validation Suite Against a Non-Docker Stack

```bash
# 1. Install Python dependencies
pip install asyncpg redis nats-py aiohttp pyyaml

# 2. Export connection parameters
export LLM_BASE_URL=http://localhost:11434
export NATS_URL=nats://localhost:4222
export DB_DSN=postgresql://pillywiggins:changeme@localhost:5432/pillywiggins
export REDIS_URL=redis://localhost:6379/0
export HEALTH_URL=http://localhost:8080/healthz
export AGENT_CHANNELS=telegram,discord

# 3. Run the suite
python tests/deployment/validate.py
```

### Docker Compose Override for Hybrid Mode

If Ollama runs on the host but everything else is in Docker:

```yaml
# docker-compose.override.yaml
services:
  puck:
    extra_hosts:
      - "host.docker.internal:host-gateway"
    environment:
      LLM_BASE_URL: "http://host.docker.internal:11434/v1"
```

Then: `docker compose -f docker-compose.yaml -f docker-compose.override.yaml up -d`

### Notes on Host Ollama

- On **macOS**, `host.docker.internal` is automatically resolvable.
- On **Linux**, Docker Engine < 20.10 may not resolve `host.docker.internal`. Add to `docker-compose.yaml`:
  ```yaml
  extra_hosts:
    - "host.docker.internal:host-gateway"
  ```
- Ensure Ollama binds to `0.0.0.0` (default is `127.0.0.1`). Set `OLLAMA_HOST=0.0.0.0` before starting Ollama.
